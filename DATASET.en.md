# manohand Dataset Documentation

[简体中文](DATASET.md) | [English](DATASET.en.md)

A human–object grasp point-cloud dataset for **human-hand point-cloud completion**: each sample = one MANO human-hand point cloud + one grasped-object point cloud. It is used to train/evaluate a diffusion model that completes the hand point cloud given a partial object point cloud.

## 1. Data Source

The dataset is built on **S2HGD** (*Single-view Scene-to-Human Grasp Dataset*):

> Yan-Kang Wang, Chengyi Xing, Yi-Lin Wei, Xiao-Ming Wu, Wei-Shi Zheng.
> **Single-View Scene Point Cloud Human Grasp Generation.** arXiv:2404.15815, 2024.

S2HGD provides about **99,000 single-object, single-view scene point clouds** covering **1,668 distinct objects**, each with one real-captured **human-grasp annotation**. This dataset fits those grasps to the **MANO** hand model and converts them into point clouds.

**Data copyright belongs to the S2HGD authors; follow their license. `Only the data comes from that dataset; the code in this project is unrelated to that paper.`**

## 2. File and Scale

`datasets/manohand.pt` is a `torch.save` dict (float32):

```
{
  "hands": Tensor[31292, 300, 5],   # human-hand point cloud
  "objs" : Tensor[31292, 2048, 5],  # grasped-object point cloud
}
```

- **Samples**: 31,292.
- **Split**: `Rdataset.py` treats the **first 500 rows as test, the rest as train** → train **30,792** / test **500**.
- **Coordinates**: normalized/scaled (`xyz` around `[-20, 20]`).

## 3. Channels

Each point of `hands` and `objs` has 5 channels:

| Channel | Meaning |
|---|---|
| `0..2` | `xyz` |
| `3` | hand-part label `{1,2,3,4,5}` |
| `4` | contact closeness `∈ (0,1)`, `= soft_distance(min distance to the other cloud)`; larger = closer |

- Hand points: channel 4 = closeness of that hand point to the grasped object.
- Object points: channel 3 = label of the nearest hand part; channel 4 = closeness of that object point to the hand.
- At training time `Rdataset.py` overwrites channel 4 with the class label (0 for the single category) as the model-input convention; the true closeness exists only in the `.pt`.

## 4. Object

- Objects come from **S2HGD**, **1,668 distinct objects** in total.
- Each sample's `objs` is the point cloud of the grasped object (source mesh sampled to 3000 points; **2048** kept in the dataset).

## 5. How the Hand Point Cloud Is Built

The hand cloud is generated by **MANO** and organized by hand part:

1. MANO parameters (`pose 48 + shape 10 + translation 3 = 61` dims) go through `ManoLayer` to produce a **778-vertex** hand mesh.
2. Each vertex is labeled with a **hand-part tag** based on MANO vertex-index ranges.
3. After **removing the palm**, each finger region is **deterministically subsampled** to yield **300** hand points per sample, with a **fixed count per part**:

| part label | points per sample |
|---|---|
| 1 | 69 |
| 2 | 60 |
| 3 | 56 |
| 4 | 56 |
| 5 | 59 |
| **total** | **300** |

Hence the hand cloud contains only 5 finger-part classes (labels 1..5) and no palm.

## 6. Conditioning Points for Completion

In the completion task, each sample's **known (conditioning) points = the first `svpoints` (default 50) points of `objs`**, i.e., **the object points nearest to the hand** (`objs` is sorted by channel 4 closeness in descending order).

Given this condition, the model completes a 300-point hand cloud via reverse diffusion; `hands` is the ground-truth hand, used for comparison/evaluation (e.g., Chamfer distance).

## 7. Generation Pipeline

```
MANO params (61)
   └─ ManoLayer forward ──► 778-vertex hand mesh
                              └─ part tagging ──► remove palm + deterministic subsample ──► 300 hand pts (5 ch)
object mesh
   └─ sample 3000 pts ──► object cloud (5 ch)
hand cloud + object cloud
   └─ contact map (closeness / nearest hand part) ──► assemble ──► dedup ──► normalize
   └─ subsample object 3000 → 2048, sort by closeness descending
   └─ save as manohand.pt
```

## 8. Intermediate Arrays (precursors of manohand)

The intermediate arrays from which `manohand.pt` was built live in `data_hand/train/` (N=**26,744**) and `data_hand/test/` (N=**4,548**); both directories share the same structure, totaling **31,292** (= number of `manohand.pt` rows):

| File | Shape | dtype | Meaning |
|---|---|---|---|
| `hand_config.npy` | (N, 61) | f32 | MANO parameters: pose(48) + shape/beta(10) + translation(3) |
| `hand_cor.npy` | (N, 778, 3) | f32 | 778-vertex hand mesh coordinates from `hand_config` via ManoLayer |
| `hand_tag.npy` | (N, 778, 4) | f32 | 778 vertices + per-vertex hand-part label |
| `hand_cpt.npy` | (N, 778, 5) | f32 | 778 vertices + part label + near-object (contact) flag |
| `hand_tag_part.npy` | (N, 300, 4) | f32 | 300 finger-part points after palm removal + deterministic subsampling |
| `hand_tag_part_tf.npy` | (N, 300, 4) | f32 | the above after pose normalization (tf = transformed) |
| `hand_near_tf.npy` | (N, 50) | f32 | 50 hand support points nearest to the object per sample |
| `obj.npy` | (N, 3000, 3) | f64 | grasped-object point cloud (3000 pts), paired 1:1 with the hand |

The main part-point chain is `hand_config → hand_cor → hand_tag → hand_tag_part`; `hand_cpt / hand_near_tf` carry contact/near-object information.
